Stampdrill HTML reports

Report format 1.0

stamp test . --html report.html and stamp load . --html report.html write one file that a machine and a person read the same way. Every measurement is in the markup, in the attributes of elements such as <stamp-plan>, <stamp-request> and <stamp-check>: times in whole milliseconds, verdicts as true and false, a load test's thresholds and its second by second series. The file is valid HTML and valid XML, so a build step can parse it with either. Opening the same file in a browser gives a page to read.

What draws it

Two files from this address, and nothing else:

https://stampdrill.com/report/1.0/report.css
https://stampdrill.com/report/1.0/report.js

The stylesheet holds the look. The module defines the elements and turns what they carry into the page: the verdict and the totals, every step and check, the actors of a concurrently block on one clock, and a load test's throughput, latency and active users over time. The version is part of the address, so a report that is already written keeps drawing the way it did when it was written.

Nothing is uploaded. The report is read where you opened it, and the page fetches nothing but those two files. To keep a copy of them beside your own reports, or to read reports on a machine with no way out to the web, point at your copy instead:

stamp test . --html report.html --html-assets ./report-assets/

In a page of your own

A <stamp-plan> or <stamp-load> element copied out of a report draws itself anywhere, from the measurements it carries. The script tag is all it needs; if the page has no stylesheet for the reports, the module adds one.

<script type="module" src="https://stampdrill.com/report/1.0/report.js"></script>

<stamp-plan name="Checkout" file="plans/checkout.stamp" passed="true" ms="412"
            iterations="1" requests="3" checks="9" checks-failed="0">
  ...
</stamp-plan>

Inside a <stamp-report> the report draws it; on its own it draws itself. No element of a report may be written self closed: <stamp-check ...></stamp-check>, never <stamp-check ... />.
